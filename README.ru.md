# Gavel AI

English version: [README.md](README.md)

Gavel AI это прототип, который ищет признаки генерации изображения. Он состоит из двух частей:

- Обученный детектор: линейный классификатор на замороженных признаках CLIP ViT-L/14. Он выдает балл и
  решение (`generated`, `uncertain`, `real`) по порогам, откалиброванным на реальных и сгенерированных
  фото.
- Символьные проверки: геометрия перспективы, анатомия кисти и согласованность света. Они работают на
  NumPy и SciPy и дают точные объяснения с визуальной локализацией. Метку они не определяют.

Результат упаковывается в строго типизированный JSON (`EvidenceProtocol`) и в аннотированное изображение.

Детектор помечает часть реальных фото, поэтому Gavel AI не утверждает, что изображение сгенерировано.
Метки описывают сигнал. Проект находится в стадии прототипа. Этот README описывает реализованное, способ
обучения и проверки детектора и места, где он ошибается.

## Архитектура

```
gavel-ai/
├── agents/                      перцептивный уровень (экстракторы)
│   ├── geometry_agent.py        LSD (запасной вариант: Hough) -> отрезки
│   ├── anatomy_agent.py         MediaPipe Hands -> 21 ключевая точка на кисть (3D и пиксели)
│   ├── light_agent.py           объекты с тенями из подключаемого провайдера сцены
│   └── synthetic.py             генераторы синтетических кистей и теней (тесты, mock-прогон)
├── core/
│   ├── registry.py              схемы Pydantic: Evidence, EvidenceProtocol, payload'ы
│   ├── observations.py          контракты агент -> валидатор (HandObservation, LightObservation)
│   ├── pipeline.py              оркестратор: детектор, агенты, валидаторы, протокол, визуализация
│   ├── learned_detector.py      признаки CLIP ViT-L/14 -> линейный классификатор -> балл и решение
│   ├── normalize.py             общая нормализация: ресайз, кроп и JPEG (обучение и инференс)
│   ├── verdict.py               решение детектора (или эвристический балл) -> метка вердикта
│   └── validators/              символьный уровень (детерминированная математика)
│       ├── homogeneous.py       однородные координаты, нормированные прямые
│       ├── perspective.py       RANSAC точек схода, DLT, дисперсия пересечений
│       ├── anatomy.py           пропорции фаланг, знаковые углы суставов, углы между пальцами
│       └── shadows.py           МНК-пересечение лучей, направленный случай
├── visualizer/
│   └── overlay.py               OpenCV: продления линий, боксы суставов, жёлтые лучи теней
├── app.py                       веб-интерфейс Gradio (загрузка, оверлей, вердикт, протокол)
├── analyze.py                   CLI для произвольных файлов изображений
├── mock_run.py                  mock-прогон на синтетической сцене (сценарии mixed, clean)
├── models/                      detector_weights.npz, thresholds.json, metrics.json
├── training/                    извлечение признаков, обучение, загрузка Wikimedia, контрольные оценки
├── tests/test_validators.py     10 юнит-тестов валидаторов и схем
├── tests/test_verdict.py        8 тестов эвристического балла и меток
├── tests/test_learned_detector.py  18 тестов порогов, нормализации, вердикта и пайплайна
├── samples/                     тестовые изображения (см. раздел о лицензиях)
├── results/                     результаты analyze.py на samples/
└── output/                      результаты mock_run.py
```

Поток данных:

```
image --> GeometryAgent --> segments --> PerspectiveValidator --> GEO evidence
image --> AnatomyAgent  --> hands    --> AnatomyValidator     --> ANAT evidence
image --> LightAgent    --> shadows  --> ShadowValidator      --> LIGHT evidence
                                  |
                                  v
                    EvidenceProtocol (JSON) + аннотированное изображение
```

Каждый этап изолирован. Если агент не может работать (нет MediaPipe, не подключен провайдер сцены,
на кадре нет кистей), этап помечается как `skipped` с причиной, а остальные этапы выполняются. Так
LLM видит разницу между «аномалия не найдена» и «проверка не выполнялась».

## Установка

Требования: Python 3.11 или новее. Детектору нужны `torch` и `open_clip_torch` (есть в
`requirements.txt`). При первом запуске open_clip скачает бэкбон ViT-L/14, около 1.7 GB. Для проверки
анатомии нужен MediaPipe 0.10.14 с legacy API `mp.solutions`, он работает на Python 3.11 и ниже. Без
torch или MediaPipe остальные проверки работают, а детектор пропускается.

Базовая установка (геометрия и свет):

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Полная установка с проверкой анатомии (Python 3.11):

```bash
uv venv -p 3.11 .venv311
uv pip install -p .venv311/bin/python -r requirements.txt "mediapipe==0.10.14"
```

Проверка установки:

```bash
python -c "import cv2, numpy, scipy, pydantic; print('ok')"
python -c "import mediapipe; print(mediapipe.__version__)"   # только для полной установки
```

## Быстрый старт

Тесты:

```bash
python -m pytest -q
```

Mock-прогон на синтетической сцене. Сценарий `mixed` содержит три намеренно заложенные аномалии,
сценарий `clean` содержит только согласованные признаки:

```bash
python mock_run.py --scenario mixed --out-dir output
python mock_run.py --scenario clean --out-dir output
```

Ожидаемый результат: `mixed` выдает три улики `CRITICAL` (`GEO-02`, `ANAT-01`, `LIGHT-01`), `clean`
не выдает ни одной. `output/overlay_mixed.png` показывает красные и жёлтые пометки для них.
Юнит-тесты должны показать `36 passed`.

Анализ реальных изображений (для проверки анатомии нужен MediaPipe):

```bash
python analyze.py samples/real/*.jpg samples/ai_generated/*.jpg --out-dir results
```

Для каждого файла создаются `<имя>_overlay.png` (аннотированное изображение) и `<имя>.json`
(протокол). В консоли выводится сводка по проверкам и найденным уликам.

Вызов из кода:

```python
import cv2
from core.pipeline import GavelPipeline

image = cv2.imread("photo.jpg")
result = GavelPipeline().analyze(image, image_name="photo.jpg")

print(result.protocol.has_critical)
print(result.protocol.to_json())
cv2.imwrite("photo_overlay.png", result.annotated_image)
```

## Веб-интерфейс

Запуск из корня проекта:

```bash
python app.py                  # откройте http://127.0.0.1:7860
python app.py --share          # временная публичная ссылка (туннель Gradio)
```

Gradio указан в `requirements.txt`. Для проверки анатомии используйте окружение Python 3.11 с MediaPipe.

Страница состоит из двух колонок:

- Слева: загрузка изображения (или вставка из буфера), список тестовых изображений, выбор детектора линий
  (`lsd` или `hough`) и порог дисперсии перспективы. Кнопка `Analyze` запускает пайплайн.
- Справа: аннотированный оверлей, оценка детектора с меткой вердикта, список проверок со статусом и
  причиной, список улик, полный `EvidenceProtocol` в JSON и файл JSON для скачивания.

Тот же анализ доступен через API под именем `analyze` (например, через `gradio_client`).

### Вердикт

`core/verdict.py` формирует метку. Работает в двух режимах.

С обученным детектором (по умолчанию в `app.py` и `analyze.py`) метка следует решению детектора по двум
порогам из `models/thresholds.json`:

| Решение | Условие | Метка |
|---|---|---|
| `generated` | балл не ниже `high` (0.4435) | `Possible generation signal (verify manually)` |
| `uncertain` | балл между `low` (0.0184) и `high` | `Inconclusive` |
| `real` | балл ниже `low` | `No generation signal` |

Символьные находки перечисляются как объяснения. Метку они не меняют.

Без детектора (нет torch или запуск с `--no-detector`) используется эвристический балл. Каждая улика
добавляет `CRITICAL` 0.60 или `WARNING` 0.25, итог считается как `1 - prod(1 - w_i)`. Метки: нет улик и
все проверки выполнены дает `No anomalies found`; нет улик при пропущенных проверках дает
`No anomalies found (limited coverage)`; ни одна проверка не выполнилась дает `Not analyzed`; улики при
балле ниже 50% дают `Suspicious`; 50% и выше дают `Anomalous`. Этот балл не калиброван.

Ни одна метка не утверждает, что изображение сгенерировано. Балл детектора не является вероятностью
генерации. Низкий балл не доказывает, что фото настоящее, а высокий балл на реальной фотографии возможен
(см. [Результаты на тестовых изображениях](#результаты-на-тестовых-изображениях)).

## Обученный детектор

### Метод

Изображение нормализуется (короткая сторона 512, центральный кроп 448, JPEG качеством 90), чтобы формат
и размер не несли сигнала о метке. Нормализованное изображение кодируется замороженным CLIP ViT-L/14
(`laion2b_s32b_b82k`). Эмбеддинг нормируется по L2, логистическая регрессия (`C = 10`, сбалансированные
классы) дает логит. Балл равен `sigmoid(logit)`.

Обучающие данные, разбиение 70/10/20 отдельно для каждого источника:

| Данные | Роль | Лицензия | Примечание |
|---|---|---|---|
| изображения nano-banana | сгенерированные, обучение | MIT (по карточке датасета) | |
| FLUX-schnell (CommunityForensics commercial, шард 0) | сгенерированные, обучение | Apache 2.0 | |
| COCO 2017, validation и test | реальные, обучение | аннотации CC BY 4.0, изображения по условиям Flickr | извлечено 20 000 |
| Open Images (`bitmind/open-images-v7-subset`, 20 шардов) | реальные, обучение | условия по каждому файлу | извлечено 15 000; условия не проверены |
| фото Wikimedia Commons (800) | реальные, обучение | CC0, public domain, CC BY, CC BY-SA по каждому файлу | список в манифесте (`training/fetch_wikimedia.py`) |

Только для оценки, в обучении не используются: DALL-E 3, Firefly 2, Firefly 3, Ideogram (из
CommunityForensics commercial, ограниченные условия на выход). Полностью исключены: FLUX-dev
(некоммерческая лицензия) и CommunityForensics-Small (CC BY-NC-SA).

Три фото из `samples/real/` не входят в обучающий набор Wikimedia. Они служат финальной проверкой и не
использовались для выбора порогов.

Пороги берутся только с калибровочного разбиения. `high` это балл, при котором 1% реальных калибровочных
фото помечаются как сгенерированные. `low` это балл, ниже которого оказываются 0.1% сгенерированных
калибровочных изображений.

Самая важная строка это Wikimedia. Реальные фото с отполированной композицией помечаются заметно чаще
целевых 1%. Добавление 560 фото Wikimedia в обучение эту проблему не убрало. Раньше проверялись две
версии: только COCO и COCO с Open Images. Версия только на COCO помечала 11% фото Open Images при пороге
COCO, то есть классификатор частично выучил источник фото.

### Почему этого недостаточно

Признаки CLIP реагируют на композицию, сюжет и обработку. Профессионально освещенный стоковый снимок может
выглядеть для классификатора как сгенерированный. Нормализация, которая убирает утечку формата и размера,
одновременно стирает низкоуровневые следы генерации, поэтому классификатор в основном видит содержание и
стиль. Калибровка на большем числе реальных фото снижает проблему, но не устраняет ее.

## Проверки

### 1. Геометрия перспективы (`geometry.perspective`)

`GeometryAgent` находит отрезки методом LSD (`cv2.createLineSegmentDetector`). Если LSD недоступен,
используется `cv2.HoughLinesP`. `PerspectiveValidator`:

1. Переводит отрезки в нормированные однородные прямые `l = (a, b, c)`, где `a^2 + b^2 = 1`. Тогда
   `|l . p| / |p_w|` равно евклидову расстоянию в пикселях от точки до прямой.
2. Отбрасывает отрезки короче 3% диагонали кадра.
3. Запускает итеративный RANSAC для до трёх точек схода. Гипотеза `v = l_i x l_j` строится по случайной
   паре прямых с углом не меньше 8 градусов. Инлайер: `|l . v| / |v_w| < 4 px`. Консенсус взвешивается
   длиной отрезка. Все гипотезы оцениваются одной матричной операцией формы `(N, H)`.
4. Уточняет каждый кластер методом DLT: `v` это правый сингулярный вектор матрицы `diag(sqrt(w)) * L`,
   соответствующий наименьшему сингулярному значению. Итерации повторяются, пока маска инлайеров меняется.
5. Строит все попарные пересечения прямых кластера. Робастная дисперсия вычисляется как
   `(1.4826 * MAD_x)^2 + (1.4826 * MAD_y)^2` и нормируется на диагональ кадра.
6. Пары, пересекающиеся вне области радиусом 10 диагоналей от центра кадра, считаются расходящимися.

Отрезки, не вошедшие ни в один кластер, помечаются как случайные (`rejected_segment_indices`).

Статусы:
- `CRITICAL`: робастный разброс выше `variance_threshold_norm` (2%) или доля расходящихся пар выше 50%.
- `WARNING`: значения выше половины порога.

Улика `GEOMETRY_PERSPECTIVE_VIOLATION` содержит точку схода, отрезки кластера и ошибочные пересечения.
Визуализатор продлевает оба отрезка каждого ошибочного пересечения до точки пересечения тонкими красными
линиями.

### 2. Анатомия кисти (`anatomy.hands`)

`AnatomyAgent` запускает MediaPipe Hands в режиме статических изображений и возвращает 21 ключевую точку
на кисть в двух системах координат: метры (world landmarks) и пиксели кадра.

`AnatomyValidator` работает с 3D-координатами, поэтому пропорции не зависят от масштаба:

1. Отношения длин фаланг `distal/proximal` и `middle/proximal` сравниваются с ориентировочными нормами
   (средние длины фаланг взрослого человека, таблица `ANATOMICAL_PHALANX_MM`). Отклонение выше 35% дает
   `CRITICAL`, выше 20% дает `WARNING`.
2. Знаковый угол сгибания сустава `alpha = arccos(a . b / (|a| |b|))`, где `a = joint - prev` и
   `b = next - joint`. Знак: `sign((a x b) . (f x n))`, где `f` это ось кисти (запястье к основанию
   среднего пальца), а `n` это нормаль ладони. Положительный знак означает сгибание к ладони,
   отрицательный означает гиперэкстензию. Допустимые диапазоны:
   - PIP: от -15 до 110 градусов;
   - DIP: от -20 до 90 градусов;
   - MCP большого пальца: от -20 до 70 градусов;
   - IP большого пальца: от -20 до 90 градусов.
   Выход за диапазон дает `CRITICAL`.
3. Угол между проксимальными фалангами соседних пальцев (указательный и средний, средний и безымянный,
   безымянный и мизинец). Больше 45 градусов дает `CRITICAL`.

Улика `ANATOMY_HAND_DEFORMATION` содержит по одному бокс-пикселю на каждый отмеченный сустав. Визуализатор
рисует вокруг них красные прямоугольники.

### 3. Согласованность источника света (`lighting.consistency`)

Проверка работает с объектами, для которых известны вершина `V` и кончик тени `S`. Луч `L -> V -> S`
прямой, поэтому точечный источник `L` лежит на прямой `SV` каждого объекта. `ShadowValidator`:

1. Строит прямые `SV` для всех объектов и находит их МНК-пересечение `L` через SVD.
2. Считает RMS-остаток `|l . L| / |L_w|` и нормирует его на диагональ. Значение выше 2% дает `CRITICAL`.
3. Проверяет, что `L` лежит за вершиной относительно тени: `(L - V) . (V - S) > 0`. Нарушение дает
   `CRITICAL`, так как конфигурация физически невозможна.
4. Если оценка `L` уходит в бесконечность (направленный свет), проверяет, что направления всех теней
   совпадают с точностью до 5 градусов.

Улика `LIGHT_CONSISTENCY_VIOLATION` содержит боксы объектов, их точки, оценку источника и попарные
пересечения. Визуализатор рисует жёлтые лучи от каждого кончика тени через вершину к оценке источника.

**Важно:** в проекте нет экстрактора, который находит объекты и тени на произвольном кадре.
`LightAgent` без подключенного провайдера сцены возвращает `skipped`. Поэтому на реальных изображениях
эта проверка сейчас не выполняется. Она проверена только на синтетических данных.

## Формат протокола

`EvidenceProtocol` сериализуется в JSON через `result.protocol.to_json()`.

Верхний уровень:

| Поле | Тип | Описание |
|---|---|---|
| `protocol_version` | строка | версия схемы протокола |
| `image` | объект | `file_name`, `width`, `height`, `analyzed_at_utc` |
| `checks` | массив | по одной записи на проверку: `check`, `status` (`passed`, `violation`, `skipped`), `reason` |
| `evidences` | массив | найденные улики |
| `detector` | объект или null | результат обученного детектора: `model`, `probability`, `logit`, `decision`, `high_threshold`, `low_threshold` (null, если детектор не запускался) |

Каждая улика (`Evidence`):

| Поле | Описание |
|---|---|
| `evidence_id` | `GEO-NN`, `ANAT-NN` или `LIGHT-01` |
| `anomaly_type` | `GEOMETRY_PERSPECTIVE_VIOLATION`, `ANATOMY_HAND_DEFORMATION` или `LIGHT_CONSISTENCY_VIOLATION` |
| `severity` | `CRITICAL` или `WARNING` |
| `description` | текстовое описание на русском языке |
| `metrics` | словарь конечных чисел с точными значениями измерений и порогов |
| `geometry` / `anatomy` / `lighting` | payload для визуализации, заполнен ровно один, соответствующий типу |

Схема строгая: `extra="forbid"`, а `Evidence` отклоняет payload, не соответствующий типу улики.
Значения `NaN` и `inf` в метриках не допускаются.

## Настройка порогов

Все пороги задаются через dataclass-конфигурации, которые передаются в валидаторы.

`PerspectiveConfig` (`core/validators/perspective.py`):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `min_segment_length_ratio` | 0.03 | минимальная длина отрезка, доля диагонали |
| `inlier_threshold_px` | 4.0 | допуск инлайеров RANSAC, пиксели |
| `min_sample_angle_deg` | 8.0 | минимальный угол пары прямых, которая сэмплируется в RANSAC |
| `min_inliers` | 4 | минимальный размер кластера |
| `ransac_iterations` | 2000 | число гипотез |
| `max_vanishing_points` | 3 | максимум точек схода на кадр |
| `max_region_factor` | 10.0 | радиус допустимой области, в диагоналях |
| `variance_threshold_norm` | 0.02 | порог робастного разброса, доля диагонали |
| `divergent_fraction_threshold` | 0.5 | порог доли расходящихся пар |
| `random_seed` | 42 | seed RANSAC для воспроизводимости |

`AnatomyConfig` (`core/validators/anatomy.py`):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `proportion_critical_deviation` | 0.35 | отклонение пропорции для `CRITICAL` |
| `proportion_warning_deviation` | 0.20 | отклонение пропорции для `WARNING` |
| `adjacent_max_deg` | 45.0 | максимальный угол между соседними пальцами |
| `bbox_padding_ratio` | 0.12 | полуразмер бокса сустава, доля размера кисти |

`ShadowConfig` (`core/validators/shadows.py`):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `min_shadow_length_ratio` | 0.02 | минимальная длина тени, доля диагонали |
| `consistency_threshold_norm` | 0.02 | порог RMS-ошибки источника, доля диагонали |
| `directional_threshold_deg` | 5.0 | порог расхождения направлений для направленного света |
| `far_light_factor` | 20.0 | оценка источника дальше этого радиуса считается направленным светом |

Пороги детектора хранятся в `models/thresholds.json` и задаются `training/train_detector.py`. Вручную их
не меняют, калибровка повторяется на обучающих данных.

`VerdictConfig` (`core/verdict.py`) задает веса и пороги эвристического балла, который используется только
когда детектор не запускался:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `critical_weight` | 0.60 | вклад одной улики `CRITICAL` в балл |
| `warning_weight` | 0.25 | вклад одной улики `WARNING` в балл |
| `anomalous_threshold` | 0.50 | балл, начиная с которого метка `Anomalous` |

## Известные ограничения

1. **Знак сгибания не подтвержден на реальных данных.** Конвенция ориентации ладони в `palm_frame`
   проверена только на синтетических руках. На реальном изображении все углы получились отрицательными,
   что указывает на систематическую инверсию. Исправление требует проверки на нескольких реальных фото
   (открытая ладонь, кулак, жесты) и, вероятно, смены знака для world-координат MediaPipe.
2. **Пропорции фаланг ненадежны при сильном сгибании и косом ракурсе.** MediaPipe оценивает глубину
   эвристически, длины согнутых пальцев искажаются. Проверка пропорций должна срабатывать только на
   кистях с малым сгибанием или сверяться с 2D-проекцией.
3. **Порог геометрии калиброван на синтетике.** Реальные фото с перспективой дают разброс 2-3% из-за
   текстур, искажений объектива и кромок. Порог нужно подбирать на размеченном наборе.
4. **У проверки света нет экстрактора.** Нужен сегментатор объектов и теней или ручная разметка. Без этого
   проверка возвращает `skipped`.
5. **Нет оценки точности.** Нет размеченного набора реальных и сгенерированных изображений, поэтому
   точность, полноту и частоту ложных срабатываний нельзя заявлять.
6. **MediaPipe 0.10.14 не работает на Python 3.12 и новее.** Для анатомии нужен Python 3.11 или ниже.
7. **Сэмплирование RANSAC.** Если угловой разброс кластера меньше `min_sample_angle_deg` (8 градусов),
   гипотезы не сэмплируются и кластер не находится. Такие кадры возвращают `passed`, а не `skipped`.
8. **Детектор помечает реальные фото.** Два из трех реальных образцов получают решение `generated`. На 800
   фото Wikimedia 11% отложенных реальных фото получают `generated`, а 33% получают `uncertain`. Классификатор
   реагирует на композицию и обработку, а нормализация стирает низкоуровневые следы генерации. Самостоятельным
   вердиктом он быть не может.
9. **Покрытие генераторов узкое.** Положительные примеры: Nano Banana и FLUX-schnell. Отложенная проверка
   покрывает DALL-E 3, Firefly и Ideogram. Midjourney, Imagen, Stable Diffusion и новые модели не проверялись.
10. **Частота ложных срабатываний различается по источникам.** При общем пороге доля `generated` на реальных
    фото составляет 0.4% для COCO, 1.5% для Open Images и 11% для Wikimedia.
11. **Метки датасета и лицензии не проверены.** `ai_05.jpg` это скриншот веб-страницы, поэтому часть меток
    образцов может быть неверной. Условия Open Images по каждому файлу не проверены. Фото Wikimedia под
    CC BY-SA могут нести условия share-alike, которые способны распространиться на веса. Это нужно решить до
    публикации весов.
12. **Эвристический балл не является вероятностью.** Он используется только когда детектор не запускался
    (см. [Вердикт](#вердикт)). Его нельзя называть шансом, что изображение сгенерировано.
## Тесты

`tests/test_verdict.py` содержит 8 тестов эвристического балла и его меток: чистый результат, частичное
покрытие, ничего не выполнено, сочетание независимых улик (параметризовано) и верхняя граница 1.0.

`tests/test_learned_detector.py` содержит 18 тестов: границы решений, упорядоченность порогов, загрузка весов
с порогами, отсутствие файла порогов, размер нормализованного изображения, вердикт для каждого решения,
символьные находки, которые не меняют метку детектора, и пайплайн с подставным детектором, сбойным детектором
и без детектора.

`tests/test_validators.py` содержит 10 тестов:

- RANSAC находит сходящееся семейство прямых и не дает на нем улик;
- несогласованное семейство почти параллельных прямых дает `CRITICAL`;
- нормальная кисть не дает улик;
- нарушение пропорции дистальной фаланги дает `CRITICAL`;
- гиперэкстензия дает отрицательный знаковый угол;
- положительное сгибание измеряется корректно;
- согласованный источник света не дает улик и восстанавливается с точностью до 1 px;
- несогласованный источник света дает `CRITICAL`;
- свет за вершинами дает `CRITICAL`;
- схема `Evidence` отклоняет payload, не соответствующий типу.

Полный набор (36 тестов) запускался на Python 3.11 с MediaPipe 0.10.14 и torch.
